# 한국사능력검정시험(기본) 기출 해설 작성 지시 v2 — "빨간펜" 구조화 해설 (회차별 에이전트용)

당신은 한국사 강사입니다. 아래 회차 50문항의 해설을 **구조화된 JSON**으로 작성합니다.
학습자가 보는 화면(앱이 렌더링):
```
정답 ②   빗살무늬 토기·움집·농경 시작은 신석기 시대의 특징이며, 가락바퀴로 실을 뽑은 것도 신석기이다.
오답 교정
  ① 철제 농기구 사용        → 철기 시대의 모습
  ③ 청동 방울로 의례        → 청동기 시대의 모습
  ④ 주먹도끼 제작           → 구석기 시대의 모습
```
왼쪽(빨간색)은 **틀린 보기 문구 그대로**, 오른쪽(초록색)은 **그 보기가 실제로 가리키는 것 / 옳게 고친 진술**입니다.

## 입력
- 문항 이미지: `D:\Workspace\korean-history-quiz\img\{ROUND}\01.webp` ~ `50.webp` (파일명 두 자리 = 문항 번호). **Read 도구로 직접 읽어** 발문·자료·보기 ①~④ 문구를 파악합니다. 문항 안에 그림·사료·지도가 있습니다.
- `D:\Workspace\korean-history-quiz\tools\v1\{ROUND}.json` — `[{n, ans, era, topic, exp}]` 정답(1~4)·시대·기존 문장형 해설(참고용, 그대로 복사하지 말고 구조에 맞게 재작성).

## 출력
`D:\Workspace\korean-history-quiz\tools\exp2\{ROUND}.json` — 50문항 배열(ensure_ascii=False):
```json
[{"n": 1, "topic": "신석기 시대 생활",
  "why": "빗살무늬 토기와 움집, 농경 시작은 신석기 시대의 특징이며 가락바퀴로 실을 뽑은 것도 신석기 시대의 생활 모습이다.",
  "fixes": [
    {"o": 2, "wrong": "철제 농기구로 농사", "right": "철기 시대의 모습"},
    {"o": 3, "wrong": "청동 방울을 들고 의례", "right": "청동기 시대의 모습"},
    {"o": 4, "wrong": "주먹도끼 제작", "right": "구석기 시대의 모습"}],
  "tip": "선택. 암기 포인트 한 문장(60자 이내). 없으면 생략"}]
```

### 필드 규칙
- `topic`: 핵심 개념 6~16자 (v1의 topic을 다듬어 써도 됨).
- `why`: 정답 보기가 옳은(부정형이면 틀린) 이유 + **자료(사료·그림·지도)에서 정답을 이끌어낸 단서**를 1~2문장, 60~180자. 정답 번호 "②" 같은 기호는 문장 안에 넣지 않는다(앱이 따로 표시).
- `fixes`: **정답을 제외한 보기 각각** 1개씩(보통 3개). `o`=보기 번호(1~4), `wrong`=그 보기 문구를 **원문 그대로 짧게**(8~30자, 단어 바꾸지 말 것), `right`=그 보기가 실제로 해당하는 시대·인물·사건 또는 옳게 고친 진술(8~45자). "틀렸다" 판정만 쓰면 안 되고 **무엇이 맞는지**를 쓴다.
  - "옳지 않은 것은?" 부정형: 정답 보기 1개만 `fixes`에 넣고(wrong=틀린 문구, right=옳게 고친 문구) `"neg": true` 추가. 나머지 옳은 보기는 쓰지 않는다.
  - 보기가 그림만 있거나(유물 사진 4개 등) 문구를 옮길 수 없으면 `wrong`에 그림이 무엇인지 짧게 적는다(예: "비파형 동검 사진" → right "청동기 시대 유물"). 정말 판별 불가하면 `fixes` 빈 배열 + `"flag": "그림 보기"`.
- `tip`: 선택. 헷갈리는 개념 대비·연도·인물 한 문장, 60자 이내.
- 정답은 v1의 `ans`를 **그대로 신뢰**. 이미지에 보이는 문항 번호가 파일명과 다르면 `"flag": "번호 불일치"`를 넣고 보고한다.

## 규칙
- 외부 해설·교재 문장 복사 금지, 평서문("~이다") 통일, 이모지·마크다운 금지.
- 작업: 1~25 → `tools/exp2/{ROUND}.part1.json`, 26~50 → `.part2.json`, 합쳐 `tools/exp2/{ROUND}.json`(50개, n 오름차순) 저장 후 python으로 검증(개수 50, fixes의 o에 정답 번호 없음(neg 제외), neg 아니면 fixes 3개 또는 flag, o 1~4, wrong/right 비어있지 않음) → part 파일 삭제.
- 다른 파일은 수정하지 않는다. 웹 검색은 필요 시 최대 4회.
- 완료 보고: 문항 수, flag 목록(n·이유)만 간단히.
